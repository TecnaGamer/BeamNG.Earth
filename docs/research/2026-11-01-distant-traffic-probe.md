## Renderer decision

The installed game's `lua/ge/extensions/render/skiaIcons.lua` explicitly documents that WorldBillboardRenderer
has no per-instance alpha interface yet; its icons fade by shrinking. It is not the first candidate for this effect.

The game's material editor exposes `instanceEmissive` and `instanceOpacity`; shader
`shaders/common/material/shadergen/defaultMat.hlsl` multiplies emission by instance RGB and opacity by instance alpha.
`lua/ge/extensions/util/trackBuilder/markers.lua` demonstrates TSStatic instance colors;
`core/groundMarkerArrows.lua` updates cached instance render data after moving a shape.
These are installed-game primary sources, not copied into this repository.

The probe uses a shared two-triangle .cdae plane and a generated radial opacity texture (761 + 2176 bytes), one
material with per-instance color/alpha, normal scene depth testing, no collision, no shadows and no light cast onto
surfaces. Assets are generated by [traffic_glow_assets.py](../../probes/traffic_glow_assets.py) with the existing
`cdae` writer and Pillow. The temporary material defaults to 80 nits; the road preview sets 320 nits to make the
small dots easier to assess against this city's bright lamps. Apparent size and brightness remain tuning variables.

A near-camera calibration row with alpha 1 / 0.5 / 0.1 / 0 confirmed differing intensity and white/red instance color.
The initial more distant row was difficult to distinguish in the city view; this was not treated as proof of a
material failure. A second probe placed a non-colliding opaque plane in front of the first calibration column:
both red/white glows behind it disappeared while the neighbouring column remained visible. This confirms normal
opaque render-depth occlusion for that controlled case; distant terrain, vegetation and transparent surfaces still
need their own checks.

## First path module and probe

[distanttraffic.lua](../../mod/beamng_earth/lua/ge/extensions/beamngEarth/distanttraffic.lua) contains pure Lua path
preparation, arc-length sampling, joined lane offsets, deterministic phase/rank, local-hour density and smooth
path-end/distance/direction fades. It is not loaded by core.lua yet. Density is tested but deliberately not applied
to the first renderer preview: a fixed small population is easier to compare.

[distant_traffic.lua](../../probes/distant_traffic.lua) is a temporary extension, loaded explicitly by the
[Python driver](../../probes/distant_traffic.py). It extracts directed chains from the current raw navgraph only to
test rendering. It is not a new far-road source, has no guaranteed separation from physical traffic and does not
validate bridge/taper alignment. Limits: 64 cosmetic cars / 128 planes, default 32 / 64; no per-frame scene object
creation; no per-frame material reload. It stops on anchor/graph replacement, mission end, explicit stop, an error,
or after ten minutes. It follows live traffic and day/night state, advances with simulation time and is independent
of the installed mod files. Initial pool creation is synchronous in this probe; production needs budgeted creation.

Example commands (checkout .venv, using its Python):

```text
python probes/traffic_glow_assets.py
python probes/distant_traffic.py start --mode calibration
python probes/distant_traffic.py start --mode occlusion
python probes/distant_traffic.py start --mode roads --count 32
python probes/distant_traffic.py status
python probes/distant_traffic.py inspect
python probes/distant_traffic.py stop
```

Before start, copy only the generated files, the pure module as `distanttraffic.lua`, and the probe as `probe.lua`
to the BeamNG user folder's `temp/beamngEarthTrafficProbe/`. Never write into the Steam game installation.
The driver loads this scratch extension with the game's `extensions.loadAtRoot`. Screenshots are asynchronous:
call `shot` once to request and again to retrieve, optionally with `--output PATH`.

## Verification and limits

- New path tests: 36 assertions passed under LuaJIT 2.1 (lupa.luajit21 in the isolated .venv), including lane-corner
  continuity, collapsed offsets, cyclic clock/phase, invalid coordinates and smooth endpoints/directions.
- Existing Lua tests: nightlights 10, geotile 17, navgraph 46 assertions passed in the same runtime.
- Existing Python navgraph suite: 12 tests passed with the checkout's earthfast version 120.
- First road preview: 32 cars / 64 planes; approximately 0.25 ms average Lua update time, maximum 0.47-0.63 ms over
  the initial short observations. These measure the probe hook only, not complete CPU/GPU frame cost or an FPS gain.
- Upper-cap preview: 64 cars / 128 planes, 1682 frames over about 42.5 s; mean 0.422 ms, maximum 1.159 ms in the
  probe hook. The user confirmed seeing motion and both colors in the 32-car preview.
- Repeated start/stop and the probe's own mission-end cleanup removed all its objects. Final inspection found no
  probe group, glow material, occluder material or loaded extension. Physical vehicle count remained 21 and the
  camera position was unchanged. Engine asset caches may retain the small immutable scratch shape/texture.
- The image contains a dense night city seen from free camera. Most source paths extend outside the current physics
  region; static collision rays do not prove occlusion against render-only far terrain/buildings. Eligible-car counts
  describe alpha targets, not the number of pixels visible through the scene.
- Screenshot artifacts and runtime files stay under ignored `build/traffic-probe/`; no game files are distributed.

Before production integration: further user assessment of size/brightness/motion; off/on CPU/GPU frame comparisons;
bounded preparation and pool growth; visual-only far path
payload with explicit heights/ownership, independent of physical AI and building settings; rebase/teleport tests.
